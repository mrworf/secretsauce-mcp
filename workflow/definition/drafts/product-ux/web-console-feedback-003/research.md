# Focused UX research — 17 October 2026

These primary sources inform the proposal; they do not override Product Owner intent or the existing security/configuration model.

- [AWS Cloudscape: page edit](https://cloudscape.design/patterns/resource-management/edit/page-edit/) recommends matching creation/editing structure, keeping primary configuration short, and a multipage view for complex configuration. Adaptation: the same domain grouping in creation, editing and review; existing-service editing offers direct section navigation instead of forcing sequential progression. We deliberately avoid accumulating nested disclosures, in response to PO-FB-059/084.
- [Cloudscape: multipage create](https://cloudscape.design/patterns/resource-management/create/multi-page-create/) organizes related tasks into steps and keeps review ordered consistently. [Wizard](https://cloudscape.design/components/wizard/index.html?tabId=api) supports direct enabled-step navigation and calls for an unsaved-work prompt when actual input exists. Adaptation: clickable five-step creation; browser history and retained non-secret work; opening a tester alone must not create dirty state.
- [IBM Carbon: data table](https://github.com/carbon-design-system/carbon-website/blob/main/src/pages/components/data-table/usage.mdx?plain=1) supplies recognizable rows, concise item actions and predictable content structure. [Cloudscape: table view](https://cloudscape.design/patterns/resource-management/view/table-view/) likewise treats resource lists as a scanning surface. Adaptation: compact service rows and distinct policy rows; no bulk administration, elaborate table customization or expanded row forms is added.
- [GOV.UK: error summary](https://design-system.service.gov.uk/components/error-summary/) combines a top-level problem summary with matching field errors and links to the affected input. Adaptation: name the unresolved imported subject and source location, link to explicit mapping, preserve other changes; use the same concrete error wording at the field and summary.
- [WAI-ARIA: modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) defines bounded focus, an accessible name, Escape handling and focus restoration. Adaptation: credential values, rule add/edit and policy test are focused tasks with a clear return to the originating service and item. No stacked dialogs.

Research is targeted to structure and interaction. The warm accent, white cards, typography rhythm and shell remain the already approved SecretSauce visual direction. No dependency on these systems’ component libraries is proposed.
