## Boundaries and retained behavior

- Generic typed key/value/list editing is limited to unusual rule options. Ordinary patterns, exemptions, policies, destinations, credentials and identity mappings have domain-specific controls.
- Forms, expert editor and importer share existing semantic drafts. No file/environment credential resolution, automatic activation, value rotation by import or historical access restoration was added.
- `constructor`, `toString`, `prototype` and punctuation-containing legacy IDs survive first import, editing, export and runtime lookup. The pre-existing raw Zod record schema does not represent `__proto__`; a mixed source containing it now fails explicitly and atomically instead of silently losing that key. New manual creation restrictions are unchanged.
- Diagnostics uses the existing `info`/`debug` semantics and existing operating draft/review/apply. The dedicated editor first guards unsaved Health work and preserves saved Limits changes. It does not enable payload/credential logging. Old operating drafts without the optional field retain the current level.
- Browser reports include keyboard tasks and desktop/320px reflow. Expanded forms checks inspect actual text ranges and document width at 200% text, including nested options, long regex/rule labels, policy, destination and complete review/read-only views.
- Whole-instance backup/recovery remains the approved self-hosted model. Actual external ChatGPT/Codex account integration remains the previously authorized external-validation exception; it is not reported as tested here. No new product feature or required feedback is deferred.
