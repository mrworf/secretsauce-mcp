## Credential research and application

Sources accessed 2026-11-16:

- [IBM Carbon modal guidance](https://www.carbondesignsystem.com/building-blocks/core/components/modal/guidelines): short, occasional management tasks suit a focused modal; consequential actions need explicit outcomes and cancel. This supports a two-field SMTP credential task, not putting an entire Settings editor inside a dialog.
- [GOV.UK password input](https://design-system.service.gov.uk/components/password-input/): visibly labeled password controls and local error messages support accurate entry. Its optional show control reveals newly typed text only here; it never permits fetching a stored SMTP secret. Do not add a redundant password-confirmation field.
- [W3C dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): move focus inside the named dialog, contain keyboard focus, support Escape before submission and restore focus after dismissal. The background is unavailable while modal.

The sources guide interaction mechanics; they do not decide SecretSauce's credential activation timing. UX-IN09/13/14 and UX-EX03 remain authoritative for that exception. Save never misleadingly claims active credentials; a successful SMTP dialog save yields a pending summary, and test email uses the applied configuration. Cancel leaves the pending/current credential unchanged. Input is cleared after completion/cancel, no browser persistence/URL/log echo; rejected secret input uses safe error text. If Save loses its response, resolve durable state before claiming success/retrying. Keep unrelated safe Settings edits during all modal transitions.
