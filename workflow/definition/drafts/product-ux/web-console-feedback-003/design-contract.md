# Service configuration experience proposal

Status: **Unapproved proposal**, feedback-003-draft-1. Extends UX3 only after UX-DESIGN-004. Does not change product authority. Source feedback PO-FB-042–124; reconciliation REC-RUN-007 / REC-DEC-008–010. Confirmed clear-value intent is resolved by STATE-09/SECRES-08; service Delete invokes the existing archive lifecycle under REC-DEC-010, without adding permanent purge.

## Direction to review

Keep the approved application shell. Services become compact full-width rows, each with independent lifecycle and draft labels. In Configuration, replace the long flattened view with a short section navigation and populated, grouped non-secret fields. Guided/Advanced is one service-wide choice. Add service retains the liked five-step guide, but every step is directly reachable; existing services use sections without being forced through creation again. Overview continues to summarize the configuration actually in use, not a duplicated configuration dump.

The primary tradeoff is one focused section at a time instead of seeing everything at once. Persistent service context and direct navigation compensate; the full JSON editor remains available. This is the one consequential design direction presented for approval. Colors, specific labels and modal proportions are designer recommendations within that direction, not facts attributed to the Product Owner.

## Constraints already settled

- Lifecycle and draft state are independent. Active is not a network-health guarantee. Drafts never silently change execution; explicit review and security acknowledgments remain. Archive, enable and current grants retain existing semantics.
- Preserve all capabilities, exact literals, stable/imported references, custom methods, arbitrary supported rule options, scanner configuration and destination variants. Routine guidance does not narrow the underlying schema.
- Credentials stay write-only. Set/Replace dialogs perform immediate actions; placement metadata remains a draft. Delete of an in-use key clears the value, retains its key, and explains both facts first (PO-FB-065/066). Missing value is not a requirement to re-enter an existing available value merely to continue the wizard.
- Assigned identities and default policy are separate gates. Owner status alone does not grant execution. Highest priority wins, deny wins an equal-priority tie, and allow defaults may still contain both effects.
- No automatic identity matching, grant expansion, host file reads or environment reads during import. Repair imported mappings in the draft and explicitly review proposed grants.
- Existing permissions, audit, recent-authentication and stale-dependency safeguards are preserved. This proposal does not decide persistence or concurrency architecture.

## Observable interaction direction

1. Service rows: a real service link with a full-row hit area excluding sibling action buttons; independent text badges for Active + Draft changes. State accent is supplementary. Lifecycle action confirmation explains immediate impact and preserves drafts. Archived remains filterable. Delete service invokes archive under REC-DEC-010: explain removal from normal use, retained configuration/history/audit, and ability to restore as Disabled. No hard purge is added.
2. Overview: two-column groups for connection, credential availability, policy and access/exceptions. No active configuration gets “No configuration is in use. This service cannot run yet.” Pending changes get one useful route to review. Current runtime exceptions remain visible.
3. Configuration: Details, Destinations, Authentication, Access & policy, Secret detection, Review changes. Render only the selected section, with descriptive headings rather than repeating the step title. One global Guided/Advanced switch. Current-versus-saved-versus-unsaved state is displayed once in the editing context; review/apply appears as the next deliberate action, not a permanent unexplained yellow banner.
4. Creation: five linked steps preserve the established order. Direct jumps do not silently save or discard non-secret form work. Final review identifies incomplete steps with links. Browser Back/Forward returns to actual section/step and origin without resetting data. Unsaved guards respond to real field changes; a tester or simple navigation alone is not an edit. Safe dirty state, incomplete-save behavior and stale revisions remain explicit.
5. Destinations: readable server cards and host matching guidance. Exact, suffix and regex receive mode-specific explanation/examples in delivery, with exact patterns retained. Service-default certificate verification is always visible, explicitly applies to all destinations without overrides. A focused per-destination advanced view exposes schemes/ports/matching/identifier and inherit/on/off override. No nested accordion. Add destination and Add credential focus/scroll to the new item, with a live announcement; no jump to top.
6. Identifiers: keep imported literals and existing identities. Service reference is MCP-visible, so it is still discoverable/copyable in contextual technical details. Auto-generated identifiers may be a convenience only if approved semantics permit it; no capability is removed. Destination/rule references move out of ordinary forms only where system-only, with exact advanced access retained.
7. Authentication: explain header/query placement with contextual names, plain prefix/suffix help and an illustrative placeholder preview that never substitutes secrets. Single-field placement hints remain visible when relevant; generic placements retain capability. Explain header ownership using the actual supported enforcement semantics. Credential metadata is visually attached to its identity and includes actor/time/version; unknown historical actor is Unknown, never inferred. Set/Replace opens one value-entry dialog; Cancel/Escape destroys transient input and returns focus. Delete opens a separate consequence dialog; a referenced key uses “Clear value” confirmation and remains visible afterward with Set value. Unreferenced key deletion remains distinct. Requests requiring a cleared value are unavailable; STATE-09/SECRES-08 distinguish applied dependencies (block new service execution) from draft-only dependencies (block that draft’s activation only). Lifecycle remains unchanged; show Active with Value missing when relevant. Historical actor attribution is source-qualified; no-op or uncertain mutation never invents a new last changer.
8. Rules: a distinct row per rule, concise effect/priority/method/path/description summary, Add rule above list, contextual Edit/Delete controls. Add and Edit use the same dialog, showing the selected rule’s literal values. Common methods are selectors, with custom/imported method values retained and editable through explicit advanced options; no comma-only input for normal work. Explanation means the reason presented for this rule’s decision, not a separate allow/deny switch. Advanced matching, scanner exceptions and typed options stay accessible without expanding the main list. Reorder controls explain boundaries and effective-order consequences; do not renumber priority automatically or drop stable ordering.
9. Policy test: focused dialog in this proposal, same inputs/results and no downstream I/O. Close returns to the precise service section and scroll/focus location; it does not mark the service dirty. If a rule dialog is open, close/keep/cancel it before opening the tester; no dialog stack.
10. Access: show what selecting a person authorizes and whether the action is current/immediate or an initial proposed grant awaiting review. Existing-service Access has usable permitted add/remove controls; read-only roles have labeled summaries. A link to shared secret detection explicitly names Settings and its wider effect, stays separate from service policy editing, and guards unsaved work. Do not imply inherited values are locally editable.
11. Import recovery: show unresolved subject, exact non-secret file location, affected services and an eligible-identity selector. Save mapping fixes the imported reference without re-uploading or losing unrelated draft changes; it does not itself grant execution. Show remaining issues and a review path. Missing eligible identities direct the permitted actor to identity registration rather than guessing mappings. Stale or unauthorized targets stay blocked with specific recoverable errors.

## Responsive and accessibility intent

At desktop use available width for paired related fields, concise lists and visible hierarchy. At narrow width preserve status, item identity, actions and recovery; stack fields and turn configuration rail into wrapping navigation. Do not hide errors or required fields. Controls have local labels, required cues, associated help and visible focus; status always has text. Use navigation links with current-page semantics for destinations, not incorrect ARIA tabs. Row links and action buttons are separate focus targets. Dialogs have names, bounded tab sequence, Escape/cancel and focus restoration; validation directs focus to summary then linked fields. At 200% text and narrow widths, both component boxes and text ranges must fit. No clipping or ellipsis conceals distinguishing policy/host literals.

## State coverage for synthesis and delivery

- Loading: labeled loading state, no fabricated values or enabled actions against unknown data.
- Empty: no services → Add/Import; no active configuration → explain non-running; no credential value → Set value; no rules → default policy remains explicit; no search matches → clear filter.
- Saved/unsaved/current: persist only through explicit save; review all service changes; no accidental immediate configuration apply. Read-only mirrors grouping without edit actions.
- Validation: local field error plus linked summary, literal inputs retained, disabled review with specific next action. Imported unknown subject includes mapping route.
- Stale dependency: preserve authorized non-secret work, show which dependency changed, reload/review; never pretend apply succeeded.
- Immediate actions: pending, confirmed success, definite failure and uncertain result remain distinct; refresh durable state before retry after uncertainty. Credential clear cannot be undone by discarding a draft.
- Permission lost/session expired: stop mutation, avoid exposing values, provide safe return/re-authentication; retain only safe work allowed by policy.
- Confirmation: Enable reviews current dependencies; Disable blocks new requests; credential clear names impact; service Delete archives with retained history and restores as Disabled.

## Prototype limits

HTML is design evidence, not a functional application. Form submission and most state transitions are inert; dialog open/close and linked page navigation are interactive. Samples do not exhaust supported advanced fields or every rule option. No live calls, secrets or production edits occur. The service Delete dialog states its archive consequence. Actual implementation must cover the above states and match the approved look at equivalent viewports, rather than treating sample omissions as removal of capabilities.
