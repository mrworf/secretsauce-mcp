# Advanced configuration and migration

**Guided** and **Advanced** modes edit one complete service draft. Saving changes creates a draft; the current applied revision keeps running. Review shows exact current/proposed scope and security exceptions. A stale base, role, credential version, lifecycle or identity security generation requires fresh review. Credential values are separate immediate write-only actions.

Policy evaluation orders the highest priority first, deny before allow at an equal priority, and preserves same-effect ties. No match uses the configured default. Guided exact matching anchors both ends; prefix matching escapes regex syntax and has ordinary string-prefix semantics (`/api` also matches `/apiary`). Imported expressions remain expressions. Policy tests use the same canonical destination/path and evaluator as execution, in a bounded worker. Select applied or saved-draft source explicitly. Results show current assignment eligibility, canonical origin/path, winning rule/default, reason and effective response protection. Query text is excluded from the displayed target. **No downstream request is sent**, credentials are not substituted, and preview never grants execution.

For migration, select **Configuration tools → Import gateway YAML and catalogs**, upload or paste the gateway YAML and optional catalogs. Add explicit identity mapping rows by entering each legacy subject and selecting its eligible local account or registered external identity. Email similarity is insufficient. Register external identities through the existing exact issuer/subject registry first. Supply missing values through the write-only credential rows (service, credential and value), or the ordinary credential create action. Imported env names and file paths are metadata; the browser never gains host-read authority. Existing credentials require the explicit Replace action. Missing mappings persist across ordinary draft saves. Open the imported service and choose **Resolve identity mappings**: each issue names the original subject, source field and other affected services. Select an eligible enrolled local account or exact registered external identity, then **Save mapping**. Correct each subject and each affected service explicitly; no email/name match is inferred. Partial corrections show the remaining issues and keep unrelated draft edits. When all mappings are corrected, **Review configuration** is available. Mapping does not activate a service or grant execution; initial assignments still require review/apply, and existing live assignments remain unchanged. Missing values also block review. If eligibility or the saved revision changes, refresh mapping status and choose again. After an uncertain response, inspect current saved mappings before retrying. Auditors can inspect this information but cannot change it. Imports never activate a service or restore grants, assignments or lifecycle. Correct a named field and validate again; a failed import accepts no partial drafts.

Review each imported service and the shared catalogs separately. Applying one configuration area advances the base revision; reload/review another area against the current revision before applying it. Owners may preserve changed inactive instance proposals; Administrators must retain current instance fields and import only their permitted service/scanner changes. Endpoint or authentication identity changes require client reconnection when separately activated. `server.resource` and OAuth issuer identify the origin, such as `https://mcp.example.org`; ChatGPT's MCP Server URL includes its path, such as `https://mcp.example.org/mcp`.

Managed encrypted state is authoritative after migration and on restart. Old YAML/environment sources do not silently override applied service settings or committed catalogs. Sanitized export contains current applied gateway configuration and catalogs, explicitly indicates missing secret material, excludes live access, and separately labels any inactive imported globals. Export is not a backup or restore archive. Configuration history excludes live identities, assignments, lifecycle, sessions/grants and credential values. Use as draft resolves current values and assignments, refuses removed dependencies and disabled-service activation, and requires ordinary exception review. A snapshot whose structural content needed redaction cannot be restored as changed regex/destination/catalog syntax; recreate a corrected draft from current configuration.

Resource bounds reject excess work rather than rewriting expressions: each YAML source ≤256 KiB (catalog form inputs ≤128 KiB), no YAML aliases, depth24/node20000/collection512 budgets; service draft256 KiB,200 rules,100 host/path expressions per rule,2048-character policy/custom-pattern sources. Sensitive-name catalogs retain their existing256-pattern/512-character source bounds. Preview has4 concurrent workers and a1-second evaluation deadline. Sensitive-name response matching batches up to10000 names in4 workers with a1-second deadline; slots remain occupied through worker termination. Secretlint retains its bounded shared pool and configured deadlines. Deadline/capacity failures fail closed without returning unscanned responses. Already-dispatched responses retain their admitted catalog configuration and live pool identity.

Exact/pattern response scanning is best-effort. Invertible encodings and downstream reflection can bypass it; trusted administrators choose destinations. It is not a universal guarantee that raw credentials cannot reach clients. Sensitive JSON processing continues to use tolerant scanner offsets and source-range replacement, preserving comments, duplicates, malformed separators and formatting outside replaced values.

## Service list and lifecycle actions

The service list shows lifecycle separately from saved draft changes and configuration attention. Active describes the applied configuration state, not a network health check. Value missing identifies unavailable applied authentication; a missing value only in a draft blocks that draft’s activation. Open a service through its name or row; search and status selection are retained when returning to the list.

Owner and Administrator row actions require confirmation. Disable stops new requests and revokes references while keeping drafts; already-dispatched work may complete. Delete archives the service, retaining configuration, history and audit records. Use the Archived filter and Restore to return it as Disabled. Enable opens configuration for explicit review of current dependencies; it does not silently apply saved changes. Resolve the indicated mapping or configuration issue when Enable is unavailable.

If a confirmation becomes stale or an action’s response is lost, refresh service state before trying again. A lost response is not proof that the change failed. Auditors have read-only service links; Members see only their permitted discovery, without administration controls.

## Allowed servers and certificates

In **Configuration → Destinations**, enter the servers and base paths that may receive requests and credentials. Exact matching allows one hostname; suffix matching includes the named DNS domain and its subdomains; regular expressions match hostname text. Broad matching is an explicit security exception reviewed before activation.

**Verify HTTPS certificates by default** applies to every destination without an override. It checks server identity; disabling verification does not disable HTTPS encryption. Each server shows its effective setting and whether it comes from the service default or a destination override. HTTP is explicitly unencrypted and does not use certificates.

A server’s **Advanced settings** opens only that destination. Connection settings retain schemes, ports, certificate override and the exact destination reference. Host matching retains multiple exact/suffix/regex literals. **Keep destination changes** returns them to the unsaved service draft; **Cancel** discards only this visit’s destination edits. Neither action saves or applies configuration. Use **Save draft**, then explicit **Review & apply** when ready. Invalid fields link to the needed correction. Existing imported `name`/`id` references remain unchanged unless deliberately edited; the MCP service reference is visible and copyable in Details.

### Credential value actions

Authentication keeps placement edits separate from values. Choose **Set value** or **Replace value** beside the key to enter a new write-only value in a dialog. **Save value** takes effect immediately; **Cancel** or Escape discards only the temporary entry. Saving the first value for a new service also saves its configuration as an inactive draft. Continuing through setup never requires a replacement value. Availability, version, last successful actor and time remain beside the key.

If a command result is unknown, check current state before reopening the value dialog. Re-enter and confirm only after reviewing current metadata; closing the dialog is not proof that a value changed. Existing unsaved placement edits remain. Delete confirms whether it clears a referenced value while retaining the key or removes an unreferenced key.
