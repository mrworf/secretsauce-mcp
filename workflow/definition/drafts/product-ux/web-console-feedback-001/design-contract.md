# Focused Settings proposal — feedback-draft-1

**Unapproved proposal.** Bounded resolution of REC-DEC-002; the existing UX-DESIGN-001 visual character is retained. PO-FB-008/011 already settle focused groups and friendly controls. PO-FB-009 suggests subtabs without requiring them. This proposal selects a compact secondary section rail because the six meaningful names fit without squeezing or hiding them; it becomes a labeled section selector on narrow screens. Existing global navigation and service tabs remain.

## Navigation and editing

Use six Settings destinations, in this order: Response protection, MCP authentication, Limits, Email, Backups & restore, Health & retention. Initial Settings entry opens Response protection; direct links/back preserve the destination. Show the selected global area and selected Settings destination using accent, weight/shape and programmatic current-page semantics. These are navigation links, not ARIA tabs pretending to be separate pages. Narrow layout uses an ordinary labeled select with the same choices and current selection. Existing global navigation and account/logout remain reachable.

Each destination renders only its own content. Start with readable applied values and an Edit action where authorized. Do not show all groups in a long accordion. Response protection may have named internal disclosures for its two catalogs and advanced options. Backups, restore and health keep their established task-specific status views, not generic configuration forms. Member has no Settings destination; Administrator can edit response protection and inspect other authorized non-secret settings; Auditor gets equivalent readable summaries without edit controls. Backups and sensitive recovery remain Owner-only.

All editable instance sections operate on the existing settings draft. Editing another section neither applies nor discards it. A persistent draft summary names changed sections and distinguishes Saved draft from Unsaved changes. Section navigation or a search jump with unsaved edits offers Stay, Save draft and continue, or Discard unsaved edits and continue. Discard here affects only unsaved current-section input; it does not delete another section's saved draft. Save never applies. Full-page Review all settings changes lists every changed section before applying the exact reviewed set atomically. No per-section partial apply is introduced. Returning to edit restores the selected section and safe values. A stale base/dependency/role requires a sanitized comparison/reload and re-review, retaining only currently authorized non-secret work. Immediate value/security actions remain distinct and can stale the draft.

Settings search matches authorized labels, help and optional technical aliases, never secrets. Results show section and field label; choosing one follows the same unsaved-edit guard, selects the section, opens the named disclosure and focuses the field or read-only value. Do not reveal unauthorized destinations or secret values. Empty search explains no matching settings; clearing search restores the selected section. An error summary can navigate to a failing field in another section, preserving safe work. Session expiry, offline uncertainty, permission loss and durable-audit failure follow existing UX-IN05; no hidden auto-save, silent replay or secret browser persistence.

## Minimum friendly-control and read-summary coverage

All preserved supported fields need a labeled control in forms, including advanced disclosures. Raw JSON/YAML is optional expert tooling, never the only route for an existing capability. General-purpose existing rule-option objects use a bounded typed key/value/list editor with add/remove rows; they are not replaced by a JSON textarea. Values whose nature is technical (regex, claim name, URL, scope) remain literal labeled inputs with explanatory help. Preserve imported literal values and matching semantics; do not infer conversions from regex to a simpler matcher. Unknown imported fields produce explicit validation errors.

Forms, optional advanced editor, import preview and read summaries use the same permitted draft without dropping fields. Show supported opaque rule-option structure through typed controls and readable nested labels; unsupported forms must preserve the value and flag a specific implementation gap, never silently flatten it. The form contract does not add configuration knobs for host-only key material, filesystem paths or startup essentials.

## Verification obligations after approval

Check all six destinations independently; no unrelated settings content loads into the same long page. Search reaches a collapsed advanced field and respects read scopes. Save/edit/back/search/discard preserve exactly the intended draft work, and review visibly names every changed section. Test invalid values, stale draft and changed permissions without hidden partial apply. Round-trip every row through forms and expert editor/import without semantic loss, including custom option objects, regexes, nested lists, identifiers and disabled configurations. Read-only summaries must remain understandable without raw object dumps. At 320 CSS px and enlarged text, inspect document width and text ranges as well as boxes; headings and actions wrap. Keyboard selection, focus return, current location and errors remain perceivable without color alone.

This is a UX proposal, not implementation, release evidence or a cross-domain pass. Final identity-reset UX will incorporate the reset specialist contract. SMTP creation/replacement remain draft/apply; Delete saved password is a distinct confirmed action, unavailable while active SMTP depends on it. Its explanation links to disabling SMTP through review/apply first. No delete-on-apply checkbox is retained. The finalized deletion contract governs recent authentication, stale drafts and non-resurrection. These details do not delay review of the independent Settings direction.
