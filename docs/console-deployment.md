# Single-instance deployment

Use [Compose](../deploy/compose.yaml) for one active application process. Provision `deploy/config/config.yaml`, protected `deploy/keys/console.key` (32 random bytes encoded as hex, mode0600), a stable RSA OAuth signing key when using built-in OAuth, and independent writable `deploy/state`, `deploy/audit`, `deploy/backups` directories. The image runs UID1000: grant that identity read-only access to keys/config and exclusive writable state/audit/backup access. Keep the console key outside application storage. Do not create/replace missing keys after a managed marker exists. Managed Docker startup holds kernel filesystem leases over app/audit mounts and uses a bounded launcher to avoid namespace writer-PID reuse; Compose uses `init:true` for signal/reaping behavior; only ESRCH authorizes stale-writer recovery. One writable state set must never serve two application instances. Keep the provided entrypoint: bypassing it bypasses cross-container leases. Host CLI work requires quiescing the app first. Unmanaged YAML/headless invocation without console environment retains the existing image contract; it does not initialize console state. Application and audit lock/checkpoint directories remain complete stable mounts.

Set initial YAML `server.listen: 0.0.0.0:8080`, `server.resource: https://mcp.example.org`, and OAuth issuer `https://mcp.example.org`. ChatGPT's MCP Server URL is `https://mcp.example.org/mcp`; Codex uses that same endpoint. Origin values omit `/mcp`. Follow [client setup](mcp-client-connection.md) and existing client documentation for scopes/PKCE/native metadata; real LLM connectivity is a separate validation step. Do not put opaque gateway references in environment/YAML or logs; they are ephemeral, subject/service-bound, and deliberately fail after restart. Persist hash-only built-in OAuth refresh snapshots in the managed state directory; preserve the stable signing material and complete audit directories. Managed encrypted configuration wins after initialization; YAML cannot silently replace it.

An operator-controlled HTTPS proxy exposes MCP/OAuth while limiting `/console` to the chosen private administration network. [Nginx example](../deploy/nginx.example.conf) includes [header rules](../deploy/nginx-proxy-headers.example.conf); install the latter as `/etc/nginx/secretsauce-proxy-headers.conf`, supply stable TLS certificate/key, and review the explicit administration allowlist. Local application binding stays loopback; never publish its raw HTTP port to the public network. Proxy access logging is off because URL/query/cookie/header details can contain proofs or OAuth values. Forwarded headers are stripped and not trusted by the application; socket source admission therefore sees the proxy identity. Size limits at the proxy and application both apply. Adjust the proxy body ceiling deliberately alongside an Owner's reviewed instance ceiling. Routine service/people/policy/auth/limits/retention management uses the console without container edits/restart.

Before restart, quiesce active downstream work, stop the single process, preserve mounts, and restart the same configuration. Graceful shutdown closes durable writers; crash startup verifies complete keyed chains/checkpoints before admission. Missing/replaced/permissive stable keys, missing audit material or evidence exhaustion must be repaired from the host. Preserve unknown-operation evidence and inspect outcomes before retrying. Audit-outage diagnostic sessions retain their restrictions after repair. Web interfaces cannot clear locks, replace keys, truncate evidence or bypass audit.

[Encrypted instance backups](console-backups.md) provide Owner manual creation/download, real job health and reviewed daily mounted-directory scheduling with30-day default retention. A mount alone does not enable the schedule: configure and apply it in Settings → Backups & restore. Protect independent recovery material separately and copy verified ciphertext off-host; local storage does not protect against host loss. Restore installation and reenrollment remain M17. A local keyed audit chain cannot defend against hostile host control or host loss.

Owner controls instance security/limits/retention; Administrator manages permitted services/catalogues and assignments to eligible existing identities; Owner controls invitations, roles, disable and assisted recovery; Auditor reads authorized non-secret configuration/evidence; Member executes assigned services and inspects own activity. Use People & Access for account lifecycle and explicit assignments, service credential rotation for write-only value replacement, and Advanced import/migration review for configuration changes. Review active client grants and security exceptions. Rotations/revocations invalidate old gateway references immediately; admitted responses retain their captured protection context. No shared legacy bearer receives console permissions automatically.

Host operators own OS/container patches, dependency-advisory triage, disk monitoring, protected-key access, TLS/DNS/proxy/mail operation, off-host storage and incident procedures. Review role/assignment/client access periodically and after staff changes. During an incident restrict network access, preserve evidence/keyed directories, revoke affected identities/grants/credentials via admitted controls where available, and reconcile unknown operations before reopening. This deployment and its reports make no SOC2 certification or throughput/SLA guarantee.

Local acceptance uses synthetic accounts/services and loopback only:

`docker build -t secretsauce-m15-local:acceptance .`

`node scripts/verify-console-docker.mjs`

`npm run build` then `node scripts/verify-console-envelope.mjs`

Scripts clean only created container/temp mounts. The local acceptance image remains available for review; remove that named image explicitly afterward if desired. No actual ChatGPT/Codex connection is implied by local protocol fixtures. See milestone15 evidence for retained-disk costs, task timings and inherited dependency advisories.
