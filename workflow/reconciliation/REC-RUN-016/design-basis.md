## U11-01 — One Access destination, explicit timing

Overview, Configuration, Access and Activity remain the shared service tabs. Access is the single guided assignment editor/view for both never-activated and applied services. Remove the Access card, selector and redirect-to-Access shortcut from Configuration; rename its fourth section **Request rules**, including read-only navigation and relevant section references. Keep policy testing, default rule behavior, priorities, overrides and exact Advanced configuration capability.

For never-activated services, Access shows **Proposed access** and eligible people/clients using the existing assignment selection language and readable identities. State that these selections take effect only after reviewed Apply; Save for later stores the shared service draft and Discard follows the existing browser/saved-proposal distinction. Use the established draft action bar rather than immediate-grant confirmation language. Empty selection is valid and grants nobody access. New unsaved services can open Access without first creating a durable record: Configuration and Access are two views of one in-memory proposal, not separate drafts or forced saves. Preserve every field/literal and selection through tab switches, Guided/Advanced, review/back, and browser Back/Forward. Navigation away still follows existing dirty guards; history contains location only. Save/Apply validates the complete shared draft under existing identity/generation/current-state gates, even if Access was not visited.

For services with applied configuration, Access displays actual current assignments and retains separate immediate confirmed grant/remove actions. Draft editing or applying a configuration cannot replay a snapshot of grants or undo independent access changes. This timing distinction is necessary and visible; consistent location does not imply identical persistence. Inactive-but-applied services follow current-assignment semantics; lifecycle is not a substitute for presence of applied configuration. Archived/read-only views preserve existing restrictions. Administrative role alone never grants execution. Imports still create independent services with zero access and no mapping task; any existing legacy reset explanation belongs to Access, not Request rules.

## U11-02 — Put the advisory with its task

Move the nonblocking **No access assigned** indicator from the former Access & policy section to the dedicated Access tab, with its explanation in Access. For initial setup it reflects current proposed selection; for applied services it reflects current assignments. Updating the correct selection refreshes the marker. Do not flag Configuration/Request rules as incomplete solely because access is empty, and do not disable review or Apply. Actual configuration blockers retain the separate yellow issue markers and precise fix links. Review may summarize proposed/current access with the correct timing; it must not create a second assignment editor.

## U11-03 — Restore service form width without widening sign-in

Source evidence identifies a concrete collision: src/consolePresentation.ts applies `.authentication-form{max-width:480px}` for compact sign-in, while renderAuthentication in src/consoleServicePage.ts adds the same class to the service form. The current service panel therefore inherits login geometry. The retained M49 authentication-desktop screenshot visibly shows a narrow480px form within a substantially wider service panel. This is supporting historical evidence, not a fresh deployed-runtime observation.

Service Authentication must occupy the available editor content column like sibling Details, Destinations and Request rules, retaining useful two-column credential fields on wide screens and one-column reflow at narrow widths. Preserve bounded form width for ordinary sign-in and Replace authenticator as the intentional short-task exception; do not widen the whole admin shell or remove compact login. Inspect multiple credential cards, no-auth, missing-value and read-only states; preserve the existing footer alignment and focused-control clearance. Scoped presentation separation is an implementation choice, not new product behavior.

## U11-04 — Delimit the exact deletion challenge

Retain the M51 destructive dialog structure, consequences, immutable target context, roles, exact-match challenge and safe focus/error behavior. Long names, embedded quotes and enlargement must remain readable and keyboard usable. M51 desktop and focused narrow captures establish the existing family, not evidence of the proposed quote change.

## U11-05 — Remove redundant instruction, retain meaning

Remove **Choose Allow or Deny** beneath the Default policy selector in Request rules (the current `fieldHints['policy-default']` source). Apply the same cleanup to equivalent Add/Edit effect selectors only where that redundant helper is actually emitted. Keep the field label, options and explanation of what happens when a rule matches, the default when none matches, and priority ordering. Do not infer that default Allow forces every rule to Deny or vice versa. Keep policy overrides and security acknowledgments unchanged.
